# Product requirements

Cauth manages long-lived OAuth tokens generated by the official `claude setup-token`
command. The default CLI and terminal UI must support these behaviors:

- Create a token through the official interactive command, then accept hidden paste.
- Import a token; privately store aliases; select, rename, replace, and remove accounts.
- Retain the prior token after a failed or cancelled renewal. Legacy pending markers
  must not block default token operations.
- Launch the official client with the selected token only in its child environment.
  Provide secret-free shell integration for ordinary Claude launches.
- Verify through a bounded official Claude request. Selection and local syntax checks
  must not be described as proof of authentication.
- Show user-assigned aliases and check results without fabricating account identity,
  subscription tier, refresh tokens, exact expiry, or guaranteed remaining lifetime.
- Preserve legacy browser profiles for migration and expose their UI separately.
- Require explicit destructive cleanup commands, including reset of damaged local state.
- Use private atomic storage and never expose stored tokens in output or command arguments.
  The official creation command displays its own new token for copying.

See [ADR 0008](adr/0008-long-lived-oauth-tokens.md) for the launch and authorization
boundary and [legacy instructions](legacy-browser-profiles.md) for compatibility behavior.
